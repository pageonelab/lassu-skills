Use Lassu for capture and production, and the host agent's browser/computer tools to operate the demonstrated app. Finish the authorized video without asking the user to write a script, edit a timeline, or review an intermediate draft. Keep questions focused on missing access, essential task information, or which daily-update items to include. Never send the finished video to another person without authorization.

Default new AI-created videos to Global access (`audience: "anyoneWithLink"`, backend `privacy: "public"`) after review and playback readiness. An explicit user audience overrides this default. Keep source drafts and review media private. Record a dedicated app window while leaving the user's desktop available; do not enter full screen, maximize, resize or reposition their windows, or take OS focus, mouse or keyboard control to improve the video. Read [window recording](references/window-recording.md) before operating the target app.

## Daily updates for coding work

Build a short list of work from the relevant project and requested time period. Use the current conversation, recent accessible AI work history, file modification times, and version-control records such as local Git changes and GitHub commits. Treat timestamps and AI summaries as leads; verify what changed and whether it is complete.

You may briefly confirm the list and ask what is missing: "I found the login fix, the new filters, and the test cleanup. Should I include these? Anything else to add?" Skip this check when the user has already specified the scope.

When useful, open the local, staging, or production app to show the results. Verify that the chosen environment includes the changes you describe. Focus on a few meaningful outcomes.

## Quick production path

For an overview diagram followed by product or code details, read [Draw walkthroughs](references/draw-walkthroughs.md). Use the one-window path or version-two source composition according to the connected app's capabilities.

1. Understand the result to show. For a daily update about coding work, use the discovery guidance above to choose a few verified outcomes. For a tutorial, show one complete path to the requested result. Briefly check that the page, account and controls are ready before recording. Avoid a full rehearsal when the path is already known.
2. Call `lassu_status`. Respect authentication, permissions and plan limits; never switch accounts or recorders to evade them. If `demo_production` is available, follow the production path below. Otherwise use ordinary recording, and explain unavailable narration capabilities only when relevant.
3. Call `lassu_list_voices` with the target `language` (such as `en-US` or `zh-CN`). The app first asks the authenticated backend whether it supports that language. If supported, `selectedVoice` uses a backend voice; if unsupported, it automatically selects an installed system voice in that language, preferring an exact locale and then enhanced quality. Use the returned `selectedVoice.voiceId` unless the user explicitly requests another supported voice. This fallback is automatic and needs no extra user confirmation. On older apps without selectedVoice, apply the same rule to the returned backend catalog and localVoices. Authentication, quota, network or synthesis errors are not a language-support answer; surface or repair those errors rather than switching providers. If neither backend nor installed system voices support the language, report `selectionError` without changing the narration language or downloading voices. The app supplies its Lassu session; never request a Deepgram key for MCP or call the provider directly.
4. Call `lassu_create_demo` with a stable idempotency key, title, the selected voiceId, language and purpose. The concrete voice is retained for retries, keeping the video's sound consistent. `targetDurationMs` is optional editorial guidance. Usually make updates and tutorials shorter than five minutes; use more time when necessary information warrants it. Do not pad short content or truncate essential information at 300 seconds.
5. Use `lassu_list_sources` with kind=window and select the exact task window, matching its identity to the window controlled by the host. The demonstrated tab must be the selected tab inside that window; the OS window may stay behind the user's work. Use a display source only when the user explicitly requests desktop recording. Source handles expire after two minutes. Call `lassu_start_recording` with this `demoId`, source, title, idempotency key and an explicit safety duration that accommodates capture and necessary holds. The capture bound and account limit are different from the editorial preference. System audio and microphone default off.
6. Wait for `state=recording` and `firstFrameWritten=true`. Mark meaningful scene boundaries with `lassu_mark_recording`, using stable keys and short labels. Markers use actual media time and exclude pauses. Perform the real actions, show their effects, and hold readable results long enough for a concise sentence group. Pause during irrelevant setup when useful. Do not record deliberation, repeated navigation, or loading just to make a video longer.
7. Always call `lassu_stop_recording`, including after an unsuccessful demonstration. With a demoId, wait for `state=draft`: the source is saved privately and upload is deferred. Read its markers and duration from `lassu_get_recording` / `lassu_get_demo`.
8. Call `lassu_update_demo` with the current `expectedRevision` and 1–20 ordered scenes. Each scene has a unique sceneId, source `startMs/endMs`, concise `text`, and an optional narrationOffsetMs (default 150). Gaps are removed. Use short, natural sentences, as if talking to a teammate: what changed, why it matters, and the result. Skip greetings, filler, promises, every mouse move, and repetitive conclusions. Use only facts observed on screen or verified in context. For live prices, mention the displayed dates/currency and that rates can change; do not imply a booking was made.
9. Optional focus uses normalized source-raster bounds measured from the actual capture, with an `atMs` and `durationMs` inside its retained scene. Focus only on a control or result that is hard to see. Keep reading holds and causal transitions. No mandatory zooms, music, title cards or sound effects.
10. Call `lassu_finalize_demo` without reviewedRevision, then poll `lassu_get_job` at pollAfterMs. It prepares at most two speech segments concurrently, caches unchanged speech, trims retained ranges, ducks original audio during narration, exports once, decodes audio and produces a review sheet. `needs_repair` contains the specific problem; for speech overflow, shorten that sentence or extend its retained source range, update the revision, then finalize with a new key. Never drop requested narration to make an error disappear.
11. At `awaiting_review`, call `lassu_get_demo` with includePreview=true. Inspect the actual decoded frames and QA timeline: right app, readable text, correct scene order, sensible focus, narration fitting each scene and expected duration. Frame samples and audio energy checks do not prove every frame or spoken word is correct. When `demo_clip_review` is available, use `lassu_inspect_demo_clip` for representative narration and motion, and for any concrete concern. Supply the current expectedRevision and output-timeline startMs/durationMs from qa.timeline; each private clip is at most 15 seconds and returns MP4 plus WAV audio. Listen for pronunciation and concise pacing, and inspect action alignment and zoom transitions with the host media tools. Inspect additional ranges where needed. If the host cannot consume the media, report that limitation rather than claiming an audio/video review passed. Aim for one export/review and at most one targeted repair; reuse good work instead of restarting the whole recording.
12. Call `lassu_finalize_demo` again with expectedRevision and reviewedRevision equal to that inspected revision, using a new key. This commits exactly the reviewed rendition. Poll until playbackReady=true, or report an actionable failure. Keep draft review entirely within the agent's work; do not ask the user to edit or approve it.
13. Apply the final audience before returning a newly created video: call `lassu_share_recording` with audience=anyoneWithLink for the Global default, or the user's explicit private/team audience, the current cloud expectedVersion, and a stable idempotencyKey. Verify the returned audience and use the actual playable URL. On a version conflict, reread the recording and reconcile its current audience; do not overwrite a newer user choice. If sharing fails, report the unfinished access step instead of calling a private result globally available. Return duration and a short description. This workflow default does not authorize widening access on unrelated existing recordings or sending the URL to another person. Never claim a silent, missing or merely queued video is finished.

## Speed and recovery

A normal run is brief preflight → one recording → one production pass → agent review → upload. Track capture, speech, render/QA, and total wall time separately; cold login and environment setup are not steady-state production latency. Do not promise an unmeasured time. Respect pollAfterMs, stop on a terminal error, and avoid unbounded polling or repeated exports. A network timeout is not permission to create duplicate captures: query/reuse the same key first.

When `demo_management` is available, `lassu_cancel_job` cancels unwanted uncommitted production, including queued work. Wait for cancellation to settle before editing or finalizing with a new key; completed speech can be reused. `lassu_list_demos` finds recoverable drafts. Use `lassu_discard_demo` only for an unwanted uncommitted draft, with its current revision; stop capture and production first. Discard removes the plan and derived media while raw sources keep their existing retention policy.

Updates invalidate rendered review; uploads require an exact revision. Uncommitted drafts survive restart and never enter ordinary automatic upload recovery. Published sources are immutable in this version: re-narrating a delivered cloud video is not an available tool. `needs_attention` during committed upload can retry finalize with the same reviewed revision and a new operation key after the cause is resolved.

## CLI and ordinary recording

Run `lassu --help` or command-specific help; CLI and MCP share the native operations. JSON results are `{schemaVersion:1,ok,data|error}`. Demo commands are `demo create`, `demo update`, `demo finalize`, and `demo get`; use `--input file.json` for scene plans and `demo get <id> --preview /absolute/review.jpg` to inspect the review sheet. On apps with private clip review, `demo inspect <id> --expected-revision <n> --start-ms <ms> --duration-ms <ms> --preview /absolute/clip.mp4` writes a bounded playable clip for the host media tools. `demo finalize --wait` stops at agent review or cloud readiness. `job wait` also returns when a stopped capture becomes a draft.

For multiple shell calls use `recording start --detach --max-duration 180s --source <id> --title Demo --demo-id <id> --idempotency-key <key> --json`, then inspect, mark, stop and wait. Choose the bound to fit the task and stop explicitly. `recording run` stays in the foreground; keep that process alive while demonstrating. The default MCP client lifecycle stops when its originating process loses its heartbeat for 60 seconds. Unrelated CLI calls do not renew that lease.

Without demo production, omit demoId. Ordinary stop finalizes/uploads immediately. Legacy macOS narration uses `prepare_narration`, measured segment durations, then narration placements on start or one `attach_narration` during capture. Record through the last spoken segment. Retry upload with `retry_recording`; removeNarration is only for an explicitly accepted silent alternative before source commit.

For a missing connection, enable AI access in Lassu preferences and use Connect Codex or Connect Claude Code in a compatible app build. Other clients use the app's copied MCP configuration for its actual installation path. The app supplies the runtime; this plugin supplies instructions only. If an older app still requires a separately installed runtime, explain that an app update is needed for the new setup experience. Do not install a global language runtime or use UI automation to bypass auth, quota or permission failures.
